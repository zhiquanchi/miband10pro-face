# 数据源实测读数（QEMU 模拟器，3.101.043 原厂固件）

方法：`native/xwf_probe.py` 生成 36 格 4×9 网格的 `probe.face`，每格左上角印源号、
下方是该源当前的读数；用 `romfs_face_swap.py setid → swap-keep` 换进
`/resource` 的当前表盘槽位，`face_debug_p67.py --ap vela_ap_bound2.bin
--resource <换好的镜像> --fresh-journal --poke sensor-charging=true` 启动后抓屏。

证据：`vendor/miband-qemu/models/band10pro/userdata/probe1/b01.png`（较早一帧）
与 `.../b04.png`（较晚一帧，间隔约 36 秒）。
两帧只有 `1011` 一格从 `003` 变成 `004`，其余全部相同。

**前提**：这台模拟器没有连真手机，所以「读 0」有两种可能 ——
(a) 该源必须由手机供数，(b) 该源在本机就没有值（如计步器没数据）。

## 已经能下的结论

1. **时间族在本机就可用**：`0811`（时）、`1011`（分，两帧唯一变化格）、
   `1812`（日）、`1012`（月）、`2012`（星期）、`0841`（电量）全部给出正确值。
   所以之前「数据不更新」不是这些源的问题，而是元素记录类型字节用错
   （`0x03000000|图集` 静态 vs `0x07000000|控件` 数据驱动），已在 `xwf_build.py` 修好。
2. **`1811` 稳定在 039 而 `1011` 在走**，两者都标着 second/minute 是 probe 的标签不准；
   按 05:39 的墙钟看 `1811` 更像分钟、`1011` 更像别的（待真机复核，不要先写进表盘）。
3. **天气族在没手机时全是 0 或哨兵值**（`2031`=0、`3031`=099），
   和「Mi Fitness 未同步就没有天气」一致 —— 天气相关的源必须真机带手机再测。
4. **`1022/1023/1024/1029/2021/3012/3812/6812` 这 8 个未命名源在无手机时就有非 0 值**，
   说明它们是本机数据（心率区间、目标、日期差值一类），是最值得下一步查的候选。

## 复现命令

```
cd miband10pro-face/native && /usr/bin/python3 xwf_probe.py
cd ../../vendor/miband-qemu
.venv/bin/python tools/romfs_face_swap.py setid  ../../miband10pro-face/native/probe.face 120917390547 /tmp/p.face
.venv/bin/python tools/romfs_face_swap.py swap-keep models/band10pro/firmware/vela_resource.bin \
    models/band10pro/firmware/vela_resource_probe.bin /tmp/p.face 120917390547
.venv/bin/python tools/face_debug_p67.py --ap models/band10pro/firmware/vela_ap_bound2.bin \
    --resource models/band10pro/firmware/vela_resource_probe.bin --fresh-journal \
    --boot-wait 70 --burst 5:12 --poke sensor-charging=true --out models/band10pro/userdata/probe1
```

## 追加分钟级采样：到底哪些源在「走」

probe1 的间隔只有 12 秒，读数上只有 `1011` 动了 003→004，样本太少。
于是加了 `vendor/miband-qemu/tools/probe_diff.py`：把 4×9 网格按格切块、
逐帧统计**真正变化的像素数**（数字是深灰压黑底，用平均灰度差会被淹没，
必须数像素），再对着 legend 报出源号。

补跑一轮 55 秒间隔的 probe2（6 帧），把两帧之间的「开机亮屏」那一跳
（第一步普遍 250~300 px，是面板从熄屏变亮，不是数据）剔掉之后，
**只有两格在持续变化**：

| 源号 | probe 标签 | 每步变化像素（probe2，55s 间隔） | 结论 |
| --- | --- | --- | --- |
| `1811` | second | 47, 41, 82, 47 | ✅ **每秒在走** |
| `1011` | minute | 67, 43, 0, 97 | ✅ **每分钟在走** |
| 其余 26 格 | — | 0, 0, 0, 0 | 值稳定（时间/日期/星期/电量等本来就分钟级以下不变，或本机就是常量） |

所以修正上一节的判读：
**`1811` 是秒、`1011` 是分**（probe 的标签这次是对的），
`0811`=005 是时；`0813`=001 是上午/下午标志。
`1022/1023/1024/1029/2021/3012/3812/6812` 这 8 个未命名源
在这台无手机的模拟器上是**非 0 但恒定**，
要判定它们到底是「本机常量」还是「手机供数」，只能回真机带手机再采一次。

复现：

```
.venv/bin/python tools/probe_diff.py \
    models/band10pro/userdata/probe2/b0{0,1,2,3,4,5}.ppm \
    --legend <(cd ../../miband10pro-face/native && /usr/bin/python3 xwf_probe.py | sed -n '/legend/,$p')
```
